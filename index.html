How I Design

Outcomes first. Evidence second. Content last.

Every program starts with what people must be able to do and what would prove it. Content comes after that, and only what closes the gap.

  1. 1 Competency Define what proficient looks like at each level, in observable behavior.
  2. 2 Outcomes Write measurable learning objectives from those behaviors.
  3. 3 Evidence Decide what shows people can do it, before anything is built.
  4. 4 Content Build only what connects each outcome to its evidence.

The competency framework is the spine. It gives every program one shared definition of proficient, so objectives, content, and assessment trace back to the same behaviors and gaps show up before launch.

The crosswalk

A crosswalk maps every outcome to the content that teaches it and the assessment that checks it. That is how I make sure nothing is taught without a purpose and nothing is assessed that wasn't taught.

OutcomeContent that teaches itAssessment that checks it
Check AI-drafted output against its source before using it Worked example and a short practice scenario Scenario item: find the unsupported claim in a draft
Decide which tasks AI should not draft Decision guide with a sensitive-task list Case-based item: sort tasks and justify each call
Document how AI contributed to a work product Job aid and a template Work sample reviewed against a checklist
